# Trash 2 cash

[เปิดเว็บ](https://saleng-digital.vercel.app/) · [ดาวน์โหลด APK สำหรับ Android](https://saleng-digital.vercel.app/downloads/saleng-digital.apk) · [GitHub Releases](https://github.com/Chawakornn/saleng-digital/releases)

## เริ่มใช้งาน

1. เปิดเว็บหรือติดตั้ง APK รุ่น 2.0.0 ขึ้นไป ผู้ใช้รุ่น 1 สามารถติดตั้งทับด้วยไฟล์ใหม่
2. เลือก **สมัครสมาชิก** ตั้งชื่อผู้ใช้และรหัสผ่าน เมื่อสมัครแล้วบัญชีจะเริ่มเป็นผู้ขาย
3. เจ้าของโปรเจกต์ใช้เมนู **บัญชี → เปิดสิทธิ์ผู้ดูแล** พร้อมรหัสส่วนตัวที่สร้างตอนตั้งฐาน รหัสใช้ได้ครั้งเดียว
4. ผู้ดูแลเปิด **จัดการข้อมูล** เพื่อแก้ชื่อชุมชน เพิ่มจุดรวมวัสดุ เพิ่มวัสดุและราคาต่อกิโลกรัม จากนั้นเปิด **รอบรับซื้อ → สร้างรอบรับซื้อ**
5. ผู้ขายเปิด **จองขายวัสดุ** เลือกวัสดุ น้ำหนัก และรอบที่ต้องการ หน้ารายการขายจะแสดงประวัติของผู้ขายที่ล็อกอิน

## ใครเห็นและแก้อะไรได้บ้าง

| บทบาท | การใช้งาน |
| --- | --- |
| ผู้ขาย | ดูราคากับรอบของชุมชน จองขายและดูรายการของตัวเอง ตรวจผลชั่ง และยืนยันการรับเงิน |
| ร้านรับซื้อ | ส่งคำขอจากหน้าบัญชี เมื่อผู้ดูแลอนุมัติแล้วจึงรับรอบ ดูรายการของรอบที่ตนรับงาน ชั่ง และบันทึกการจ่าย |
| ผู้ดูแลชุมชน | จัดการจุดรับ รอบ และสมาชิกที่อยู่ในชุมชนที่ได้รับมอบหมาย |
| ผู้ดูแลระบบ | ตั้งราคา จัดการชุมชน บทบาท ร้าน และข้อพิพาทจากเมนูจัดการข้อมูล |

ราคากับตารางรอบเป็นข้อมูลร่วมในชุมชน การจอง รูป และประวัติการขายจำกัดตามบัญชีหรือหน้าที่ของผู้ใช้ ผู้ใช้ทั่วไปสมัครเป็นผู้ขายเท่านั้น การเปลี่ยนบทบาทตรวจบนเซิร์ฟเวอร์

## ข้อมูลอยู่ที่ไหน

รุ่น 2 ใช้ฐานข้อมูล SQLite แบบมีโฮสต์บน **Turso** โครงการ Vercel ที่ใช้งานจริงเชื่อมกับฐาน **saleng-digital-data** ผ่าน environment variables ฝั่งเซิร์ฟเวอร์ `TURSO_DATABASE_URL` และ `TURSO_AUTH_TOKEN` เจ้าของเปิด Vercel → Saleng Digital → Storage หรือ Marketplace แล้วเปิดทรัพยากร Turso นี้ การแก้ราคาหรือรอบตามปกติทำได้จากหน้าเว็บด้วยสิทธิ์ผู้ดูแล

| ตาราง | ข้อมูล |
| --- | --- |
| User / Session | ชื่อผู้ใช้ แฮชรหัสผ่าน บทบาท และเซสชันเข้าสู่ระบบ |
| Community / Point / Material / Price | ชุมชน จุดรับ วัสดุ และประวัติราคา |
| Round / Booking / BookingItem | รอบรับซื้อ การจอง เจ้าของรายการ ชนิดวัสดุและน้ำหนัก |
| Revision / WeighItem / Payment / Receipt | ผลชั่งแต่ละรุ่น รายการจ่าย และการยืนยันรับเงิน |
| Attachment / Notice / Audit | รูปแนบ การแจ้งเตือน และประวัติการทำรายการ |

ดูโครงสร้างทั้งหมดใน `server/schema.sql` ฐานใหม่เริ่มด้วยชุมชนตั้งต้นหนึ่งแห่งและข้อมูลระบบสำหรับเปิดสิทธิ์เจ้าของ รายการซื้อขาย บัญชีสาธิต และราคาตัวอย่างเริ่มว่าง รหัสผ่านใช้ scrypt พร้อม salt แยกแต่ละบัญชี เซิร์ฟเวอร์ส่ง session cookie แบบ HttpOnly, Secure มีอายุเจ็ดวัน และเก็บเฉพาะแฮชของโทเคนในฐาน

รุ่น 1 เคยเก็บ SQLite ผ่าน sql.js ที่คีย์ `saleng-showcase-db-1` ใน sessionStorage ของแท็บเว็บ หรือ localStorage ใน APK เดิม รุ่น 2 เริ่มข้อมูลแยกตามบัญชี ผู้ที่มีข้อมูลเก่าบนเครื่องจะเลือกเก็บหรือลบได้ ข้อมูลเดิมจะไม่ถูกอัปโหลดเข้าบัญชีใหม่

## การซิงก์และการอัปเดตแอป

- เมื่อกดบันทึก API ตรวจผู้ใช้และสิทธิ์ก่อนเขียนลงฐานกลาง การแก้หลายตารางในหนึ่งงานใช้ transaction
- หน้าที่เปิดอยู่ตรวจรุ่นข้อมูลทุกประมาณ 3.5 วินาที และตรวจเมื่อกลับเข้าแอป ฐานมี trigger เพิ่มเลขรุ่นเมื่อข้อมูลเปลี่ยน รวมถึงเมื่อแก้ตารางผ่านคอนโซล หน้าจอโหลดเฉพาะข้อมูลที่บัญชีมีสิทธิ์เห็น ระยะเวลาจริงขึ้นกับเครือข่าย
- APK รุ่น 2 เปิดเว็บจากโดเมน production ของโปรเจกต์ จึงต้องเชื่อมอินเทอร์เน็ต เมื่อ deploy หน้าเว็บแล้ว ให้เปิดแอปอีกครั้งหรือโหลดหน้าใหม่เพื่อใช้ UI ล่าสุด
- ถ้าแก้ส่วน Android เช่น สิทธิ์เครื่อง การแนบไฟล์ หรือการพิมพ์ ให้เพิ่ม versionCode และสร้าง APK รุ่นใหม่ด้วยกุญแจเดิม
- รุ่น 1 เป็นเดโมออฟไลน์ ผู้ที่ติดตั้งรุ่นนั้นต้องติดตั้ง APK รุ่น 2 ก่อนใช้ระบบบัญชีและการซิงก์

## แจ้งอัปเดตในแอป Android

เมื่อเปิดแอป กลับเข้าแอป หรือเปิดแอปค้างอยู่ ระบบตรวจประกาศรุ่นล่าสุด (ขณะเปิดค้างจะตรวจทุก 60 วินาที) ถ้ามีรุ่นใหม่ ผู้ใช้เลือก **อัปเดต** หรือปิดแถบเพื่อทำงานต่อได้ เปิด **บัญชี → ตรวจอัปเดตแอป** เพื่อตรวจเองได้ทุกเวลา

ใน APK ตั้งแต่ 2.2.0 บน Android 10 ขึ้นไป ปุ่มอัปเดตส่งไฟล์เข้าระบบดาวน์โหลดของเครื่อง เมื่อเสร็จให้เปิดไฟล์แล้วแตะ **อัปเดต** ในหน้าติดตั้งของ Android บน Android 8–9 ปุ่มเปิดเบราว์เซอร์ รุ่น 2.0–2.1 จะให้คัดลอกลิงก์ไปเปิดใน Chrome สำหรับการอัปเดตครั้งแรก และรุ่น 1 ออฟไลน์ต้องเปิดเว็บเพื่อดาวน์โหลดเอง

การส่งรุ่นใหม่ให้เพิ่ม `android:versionCode` และ `android:versionName` ใน `android/AndroidManifest.xml` แล้วรัน `npm run build:apk` ด้วยกุญแจเดิม สคริปต์ตรวจลายเซ็นและสร้าง `public/downloads/android-release.json` จาก manifest ให้ commit และ deploy ไฟล์ JSON กับ APK ในรุ่นเดียวกัน แถบจะแสดงเฉพาะเมื่อรุ่นที่เผยแพร่ใหม่กว่าแอปในเครื่อง

## พัฒนาใน VS Code

ใช้ Node.js 22.12 ขึ้นไป จากโฟลเดอร์ที่มี package.json เรียก `npm ci` แล้ว `npm run dev` เปิด URL ที่ Vite แสดง การรันครั้งแรกสร้างฐานทดสอบใน `.local-data/saleng.sqlite` และรหัสเปิดสิทธิ์เจ้าของที่ `.local-data/owner-code.txt` ให้ใช้ฐานนี้ทดลองข้อมูลก่อนเผยแพร่

`src/pages/` เป็นหน้าจอ React ส่วน `src/account.css` ดูแลหน้าเข้าสู่ระบบ การปรับหน้าจอมือถือ และแอนิเมชัน รองรับการตั้งค่าลดการเคลื่อนไหวของอุปกรณ์ `api/[route].js` รับคำขอบัญชี ข้อมูล รูป และการทำรายการ ส่วน `server/` ตรวจสิทธิ์ ทำธุรกรรม และเรียกฐานข้อมูล

สำหรับฐาน Turso ใหม่ที่ยังว่าง ตั้งค่าการเชื่อมต่อใน environment ฝั่งเซิร์ฟเวอร์ แล้วเรียก `node server/init-db.js /path/to/private-owner-code.txt` ครั้งเดียว คำสั่งนี้ตรวจว่าฐานว่างและเขียนรหัสเจ้าของลงไฟล์ส่วนตัว ห้ามนำไฟล์รหัสหรือคีย์ลงนามขึ้น repository

## สร้างและเผยแพร่

- **เว็บ** ใช้ `npm run build` สร้างส่วนหน้าที่ `dist/` ทดสอบทั้ง API และหน้าเว็บด้วย `npm run dev` Vercel ติดตั้ง API จาก `api/` และ deploy อัตโนมัติเมื่อ push เข้า main
- **APK** ใช้ Python 3, JDK 21, Android Platform 35 และ Build Tools 37.0.0 ตั้ง `JAVA_HOME` กับ `ANDROID_HOME` แล้วเรียก `npm run build:apk` ไฟล์ผลลัพธ์อยู่ที่ `public/downloads/saleng-digital.apk`
- เครื่อง build ใช้ keystore และรหัสผ่านใน `.android-signing/` หรือระบุไฟล์ด้วย `SALENG_KEYSTORE` และ `SALENG_PASSWORD_FILE` กุญแจต้องมี alias `saleng` โปรดสำรองไว้ในที่ส่วนตัวเพื่อออกอัปเดตทับรุ่นเดิม
